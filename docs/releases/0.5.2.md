# Open Markdown Review 0.5.2

Regular release with known limitations; **not approved for the professional pilot**. This patch adds review-removal actions and improves reviewer identity and navigation in VS Code. Core wire version remains 0.5.0; there is no package migration or second source of review content.

## Added and fixed

- Update Sharp and its native/WASM packages to 0.35.4, and the affected js-yaml 4 dependency to 4.3.2, addressing the [Sharp/libheif advisory](https://github.com/advisories/GHSA-rgj7-g3m4-5g8c) and [js-yaml merge-budget advisory](https://github.com/advisories/GHSA-2883-xcg3-v3hh). Dependency audit gates remain enabled.

- **Remove Review from List** disconnects a current or legacy review locally without deleting shared files. Explicit reconnection works even after a restart; automatic legacy discovery does not bring a removed review back.
- **Delete Review…** confirms the exact folder and inventory before moving the entire dedicated package to OS Trash/Recycle Bin. It protects source/workspace roots, rejects links/junctions and unexpected top-level files, checks for changes during confirmation, and coordinates local operations. There is no permanent-delete fallback.
- Removal closes all of that review's toolbox tabs and clears its active selection and authoring-resume shortcuts, while preserving other reviews and private recovery journals. Late writes from closed toolboxes are rejected.
- Creation passes both **Reviewer ID** and **Display Name** into the VS Code toolbox. Later edits are remembered privately per review, including across reopening; a received review never borrows its creator's identity.
- One **Reviews** list replaces the duplicate “Reviews” and “Review Packages (0.5)” interfaces. Creation, opening and tab focus update **Active Review** and the status bar. Closing a toolbox retains the selection; sidebar commands reopen it and wait until the toolbox is ready.
- Windows drive/directory casing aliases are treated as one local connection for registration, active selection, removal and reconnection; display and private journal paths retain their original spelling.
- Regression tests cover deletion cancellation/failure, changed and unsafe folders, active-review cleanup, duplicate tabs, reconnection, identity handover and the first comment's author. Slidev navigation assertions wait for the selected slide's evidence.

## Installation and compatibility

- Windows x64: `open-markdown-review-0.5.2-win32-x64.vsix`.
- Other supported VS Code platforms: `open-markdown-review-0.5.2-portable.vsix`.

Both packages include SHA-256 checksum files and standard VSIX metadata without a pre-release marker. Use **Extensions: Install from VSIX**, then reload the VS Code window. This release does not automatically replace executable HTML in existing shared reviews; **Markdown Review: Update Portable Browser Client** remains explicit and backed up. VS Code uses its installed trusted toolbox. Browser participants continue opening `OpenMarkdownReview.html` and granting folder access.

Existing 0.4 packages retain the legacy reader. Markdown, Mermaid, tables, images, attachments and optional Slidev static review remain available. Replies, decisions, suggested edits and audit exports keep their existing wire semantics. Whole-package filesystem deletion does not invent a `review.deleted` event or edit individual historical events. Previous tags, binaries and checksums are unchanged.

## Validation and limitations

The changes passed **106 unit/protocol tests**, **four real-browser scenarios** and **isolated VS Code extension-host checks** on macOS before publication. The release workflow independently gates publication on Linux/portable and Windows validation, browser and extension-host tests, dependency audits, packaging and checksums for the tagged source.

- **SMB testing is skipped and remains untested**, as requested because an authorized CI-only share is unavailable. No shared-drive compatibility claim is made.
- Trash transport itself is not qualified by simulated-trash tests. If a drive/provider cannot use Trash/Recycle Bin, deletion fails without a permanent fallback. Inspect the folder after a storage error. Stop other VS Code, browser and CLI writers before deleting a shared review: deletion may synchronize to other participants, and local checks do not lock other machines or eliminate filesystem races.
- Removal closes tabs and discards unsaved drafts only after confirmation. Recover a successfully trashed package using the OS, then reconnect it. If the review is itself the open workspace, open the parent/source workspace before deleting. Git changes are never committed or pushed automatically.
- **Professional-pilot qualification remains incomplete.** Mermaid interruption, participant cancellation/filesystem safety, local Windows browser permissions, reference-workload performance and independent usability gates remain open. A regular release label does not override [release-qualification.json](../../release-qualification.json).
- Reviewer identities remain self-asserted and unsigned. Audit hashes do not authenticate reviewers or establish that disconnected participants have synchronized. Slidev static-review restrictions and the isolated author-test-runtime advisory exceptions documented in [0.5.1](0.5.1.md) still apply.
