# Open Markdown Review 0.5.6

Focused WSL/remote-workspace reliability hotfix with known limitations; **not approved for the professional pilot**. The framework-neutral core wire version remains 0.5.0, so review packages remain compatible with 0.5.x clients that support their declared capabilities.

## Corrected behavior

- A missing or invalid package remembered from an earlier session remains visible as unavailable without failing extension activation or being repeatedly restored as active.
- New creation chooses the next missing or empty `.review[-N]` folder instead of reusing a partial package. Package creation below `.local-preview` is refused, and generated preview Markdown is excluded from discovery.
- WSL, SSH, Dev Container and other remote extension hosts do not offer **Delete Review** because VS Code cannot guarantee a recoverable OS Trash/Recycle Bin there. **Remove Review from List** remains available and never changes shared files.
- Recovery failures identify the exact immutable path. Acknowledged evidence is still never reconstructed automatically.
- Extensionless PNG, JPEG, GIF, WebP and SVG images are recognized from their captured bytes. Unsupported-image errors identify the source Markdown and reference.

## Extension-host artifact selection

The desktop OS and extension host can differ. The extension explicitly runs beside workspace files:

- Use `open-markdown-review-0.5.6-win32-x64.vsix` for a workspace opened by a local Windows x64 extension host.
- Use `open-markdown-review-0.5.6-portable.vsix` for WSL, SSH, Dev Containers and other supported hosts, including WSL sessions displayed by Windows VS Code.

Install the artifact in the Extensions section for the active host. **Developer: Show Running Extensions** identifies where the extension is executing.

## Compatibility and limitations

- Existing complete 0.5 review packages are unchanged. No protocol event, manifest, revision, permission or storage-layout change is introduced.
- An incomplete package that has lost acknowledged files remains intentionally fail-closed. Preserve it for inspection and create a new package in a different empty durable folder.
- **SMB remains untested**, because an authorized CI-only SMB share is unavailable. No SMB compatibility or performance claim is made.
- Reviewer identities remain self-asserted and events unsigned. Role restrictions remain workflow rules rather than authenticated authorization.
- Professional-pilot qualification remains incomplete; see the checked-in implementation status and acceptance criteria.

Publication requires a separate explicit release authorization after CI and packaging qualification.
