# Open Markdown Review 0.5.0 — evaluation pre-release

This release is for evaluation and feedback. It is **not approved for the professional pilot or production sign-off**. Professional-pilot approval remains false; publication does not close the outstanding qualification gates.

## Included

- One local-first review package and shared reviewer toolbox in VS Code and a generated, double-clicked HTML file. No application server or browser extension.
- Parameter-driven CLI and graphical VS Code creation, multiple reviews, custom storage folders and immutable revisions.
- Markdown, Mermaid diagrams, images, tables/cells and captured external attachments.
- Anchored comments and replies, linked highlights, accept/reject decisions, resolve/reopen, strikeout/replacement suggestions and explicit source application.
- Revision approval/rejection/withdrawal, concurrent event publication, bounded caching and eventual synchronization.
- Audited whole-revision PDF export including comments, replies, decisions and exact-byte evidence; resumable publication and export retry.
- Protocol 0.5 schemas and shared implementation; existing 0.4 packages retain their legacy VS Code reader without silent migration.
- MIT licensing for project code and a separate non-binding M.I.R.D.A. philosophy, with bundled third-party notices.

## Install

Download the appropriate VSIX and its matching SHA-256 checksum:

- **Windows x64:** `open-markdown-review-0.5.0-win32-x64.vsix`.
- **Other supported VS Code platforms:** `open-markdown-review-0.5.0-portable.vsix`.

In VS Code choose **Extensions: Install from VSIX**, select the downloaded file, and reload if prompted. These packages are explicitly marked pre-release.

Authors create a review from the Review Activity Bar or the CLI. Browser participants receive the complete review folder, double-click `OpenMarkdownReview.html`, explicitly grant access to the adjacent folder, and enter their reviewer identity. Browser access is not inherited Windows authentication. VS Code opens that same entry file with its installed trusted client.

## Validation and limitations

The merged implementation baseline passed Linux/portable and Windows CI. The tagged release workflow must additionally pass the core/protocol and release-policy tests, browser and VS Code integration checks, dependency audits and target packaging before publishing these assets.

- **SMB remains untested.** CI-only share provisioning is unavailable and testing is excluded by user decision. No SMB compatibility, ACL, interruption-recovery or latency qualification is claimed.
- Actual local Windows browser folder grants, restart/revocation and enterprise permission-policy scenarios remain unqualified. The native-picker fixture depends on excluded SMB setup. Origin-private storage/IndexedDB and native-bridge tests do not replace native permission evidence.
- Mermaid lacks the specified hard interruptible rendering deadline. Full participant cancellation and CLI error-class parity remain incomplete.
- Adversarial native path replacement, external-editor races, platform ACL/replacement and power-loss durability are not fully qualified. Keep source control and backups.
- Optional presentation-extension conformance, complete accessibility/selection coverage, reference-workload latency/memory and independent user-task acceptance remain outstanding.
- Reviewer identities are self-asserted; events are unsigned. Audit hashes identify observed exact bytes, not authenticated people or globally complete synchronization.

Use non-critical evaluation material and retain backups.
