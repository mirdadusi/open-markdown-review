# Open Markdown Review 0.5.3

Regular release with known limitations; **not approved for the professional pilot**. This rebuilt patch completes the review workflow, portable-package publication and browser cold-open work accumulated for 0.5.3. Core wire version remains 0.5.0.

## Added and fixed

- Comment and Suggest actions remain reachable after deep scrolling. Comment and suggested-edit cards link to their exact source positions, and clicking either document marker returns to its finding card.
- New reviews use initiator-managed finding control. Reviewers may reply while a thread is open; only the immutable manifest initiator may decide, close, or reopen it. A closed finding exposes only Reopen to the initiator and no write actions to other reviewers until reopening.
- The toolbox always displays the participant's current stance. Approve and Reject are available without an active stance; after either decision, only Withdraw is available; withdrawing restores Approve and Reject.
- The findings side panel defaults to comments and suggested edits from every Markdown document. It can be narrowed to the selected document, keeps document locations and navigation, receives off-document peer findings through live synchronization, persists its VS Code view preference, explains empty scopes, and remains reachable in narrow editor columns.
- PDF export is a self-contained offline review archive. It includes a deterministic challenge register, every frozen document with a per-document challenge map, a dedicated comments/responses/findings section with complete replies and lifecycle history, participant stance history, rendered Mermaid/images/tables, external-reference disclosures, internal links, and the exact audit appendix/inventory. The PDF is derived evidence; `.review/` remains the sole source of truth.
- New packages can declare the optional `sanitized-html-v1` capability and `commonmark-gfm+sanitized-html-v1` renderer profile. VS Code, the portable browser and PDF export then share a fail-closed structural HTML subset for headings, paragraphs, emphasis, lists, links, images, code, quotes and tables. Scripts, styles, embedded frames, event handlers and unsafe URL schemes remain inert.
- Raw HTML images and explicit attachment references are captured as content-addressed package resources; external links are inventoried for audit. Text, images, tables and cells retain source anchors so findings navigate consistently between rendered content and discussions. Packages that do not declare the capability continue to show raw HTML as inert text.
- New reviews generate a review-named `Review-<name>.html` launcher bound only to the expected review ID, title and exact manifest digest. The browser rejects a different selected folder and reconnects automatically only while its previously granted directory permission remains available.
- VS Code can publish a verified complete package copy to an empty local, synchronized, shared-drive or Git folder. It rejects links and unexpected content, hashes and re-reads every file, validates the destination, checks the source again and then switches the active connection without deleting the original package.
- A separate private **Link Local Source Workspace** workflow reports exact, changed and missing reviewed documents without placing native source paths in shared evidence. Multi-root creation explicitly selects one Markdown source root; extra roots remain resource-only.
- Explicit DOCX, legacy/current Visio and EMF attachments can be carried as bounded content-addressed originals behind their review rendering without executing them.
- Cold open now reports manifest, event and rendering progress immediately. Ordinary Markdown reviews admit verified descriptors first and load only the selected document and visible resources; approval and audit/export paths still perform a fresh whole-revision verification. On the 49-document/300-resource reference package this reduced local admission from 205 reads/16.8 MB to 4 reads/216 KB before the first document.
- Regression coverage includes deterministic archive finding references, simultaneous and cross-document participants, review-wide filtering/navigation, incremental updates, scope restoration, responsive widths, initiator-only lifecycle controls, stance transitions, and complete PDF export independent of UI filters.

## Installation and compatibility

- Windows x64: `open-markdown-review-0.5.3-win32-x64.vsix`.
- Other supported VS Code platforms: `open-markdown-review-0.5.3-portable.vsix`.

Both packages include SHA-256 checksum files and standard VSIX metadata without a pre-release marker. Install through **Extensions: Install from VSIX**, then reload VS Code. Existing generated HTML clients are executable artifacts and are not replaced automatically; use **Markdown Review: Update Portable Browser Client** with its explicit backup and confirmation to migrate a legacy generic filename or obtain the new browser UX.

Existing 0.4 packages retain the legacy reader. Existing 0.5 packages remain readable under their declared capabilities; creator-controlled lifecycle semantics apply only when the package declares that capability. Existing review evidence is not rewritten or migrated.

## Validation and limitations

Before release preparation, the changes passed **112 unit/protocol tests**, **six real Chromium scenarios**, PDF content/internal-link inspection, sanitized-HTML rendering/export checks, the complete 49-document/300-resource reference-package audit, and isolated VS Code extension-host checks on macOS. The tag-driven release workflow independently repeats Linux/portable and Windows validation, browser and extension-host tests, dependency audits, packaging, and checksums before publication.

- **SMB remains untested**, because an authorized CI-only SMB share is unavailable. No SMB compatibility or performance claim is made.
- **Professional-pilot qualification remains incomplete.** Interruptible Mermaid rendering, remaining participant cancellation and platform source-save durability, containment-race and optional-extension conformance, local Windows browser folder permissions, native Windows relocation/fault injection, shared-drive reference-workload performance, and independent user-task acceptance remain open.
- Reviewer identities remain self-asserted and unsigned. Creator-only controls are consistent workflow rules, not authenticated access control. Audit hashes do not authenticate participants or prove that disconnected clients have synchronized.
- Browser folder access remains subject to Chrome/Edge permission behavior and enterprise policy. A file-based HTML client cannot silently inherit Windows identity or access neighboring files without a browser grant.
